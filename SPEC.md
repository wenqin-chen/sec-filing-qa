# sec-filing-qa — SPEC v1.0 (synthesized from Design 0 + grafts; 2026-09-11)

Grounded question answering over SEC 10-K/10-Q filings: hybrid RAG with page-level, verified citations, plus a tool-using agent (filing search, SQL over XBRL facts, curated fact lookup, calculator), served by FastAPI in Docker, deployed to GCP Cloud Run and Azure Container Apps, and benchmarked on FinanceBench (150 open questions) with a reproducible, per-question-logged, offline-rescorable harness comparing OpenAI and Anthropic models.

## 1. Goals
1. A pip-installable, MIT-licensed reference implementation of document-QA for finance that is *trustworthy*: every number traceable to a filing page (or an XBRL fact with accession number), abstention scored, unverifiable citations flagged never hidden.
2. The first open, reproducible FinanceBench harness with per-question logs, closed-book and oracle brackets, a failure taxonomy, and cross-vendor cost/latency/accuracy comparison that anyone can re-score with zero API keys (replay cassettes).
3. Honest resume backing for: LLMs, AI Agents, RAG, Model Evaluation, FastAPI, Docker, GCP & Azure deployment, OpenAI & Claude APIs.
4. Every design decision explainable in an interview (docs/decisions.md ADRs); boring components only.

## 2. Non-goals (v0.1; listed in README so cuts read as decisions)
No UI beyond /docs; no vector database; no LangChain/LlamaIndex/SDK tool-runner; no multi-turn chat; no streaming; no public ingest endpoint; no cross-encoder reranker; no table-aware PDF extraction (pdfplumber ablation is future work); no auth beyond an optional demo API key; no frames-API cross-company tool; no market data; 3-repeat variance runs and the OpenAI-embedding ablation are post-v0.1.

## 3. Architecture (one process, one DuckDB file, Python 3.11)
```
 FinanceBench PDFs ──pypdfium2──┐                      ┌── /ask (rag|agent|closed_book)
 EDGAR 10-K/10-Q HTML ─bs4──────┼─ pages ─ chunk ─ embed ─► DuckDB index.duckdb ◄──┤   FastAPI  ── Docker ── Cloud Run / ACA
 EDGAR companyfacts JSON ───────┘  (documents, pages, chunks[+FLOAT[dim]], xbrl_facts, financials view, FTS)
                                                        ▲
   Retriever(bm25 | dense | hybrid=RRF) ── rag.answer ──┤── CitationVerifier ── Answer{citations[verified], grounded, trace, usage, cost}
   agent.run_agent (manual loop, 6 tools) ──────────────┘
   eval.runner ── judge (fixed claude-sonnet-5) ── metrics ── results/<run>/predictions.jsonl ── secqa report ── RESULTS.md
```
Layers and ownership (see modules): core (contracts/settings/textnum) → providers, embeddings, edgar, ingest, store, grounding → xbrl, retrieval, indexing → rag, agent → eval, api → cli, ops, docs.

Data flow for one question: question (+optional ticker/doc filter) → Retriever.retrieve → LLM (single call with numbered passages, JSON-schema output) or agent loop (tools over local DuckDB only) → CitationVerifier → Answer → JSON response (API) or EvalRecord (harness).

## 4. Data
### 4.1 Sources
- FinanceBench: HF `PatronusAI/financebench`, split **`train`** (verified 2026-09-11: single split, 150 rows). Fields used: financebench_id, company, doc_name, question_type, question, answer, justification, doc_link, doc_period, evidence[{evidence_text, doc_name, evidence_page_num, evidence_text_full_page}]. Licence CC-BY-NC-4.0 → evaluation only; never redistributed in git (results files carry only financebench_id — see 9; recorded cassettes are Release assets that store full prompts, so they contain dataset text and are shared under CC-BY-NC-4.0 with attribution). `evidence_page_num` is **0-indexed** per the PatronusAI README; secqa uses 1-based physical page numbers everywhere, so `page_num = evidence_page_num + 1`; `scripts/check_page_indexing.py` verifies this on 25 sampled questions (evidence_text must be found on that pypdfium2 page after whitespace normalisation) and writes docs/DATA.md; no recall number is published until it passes ≥ 90%.
- PDFs: `https://raw.githubusercontent.com/patronus-ai/financebench/main/pdfs/{doc_name}.pdf` (~80 unique docs referenced by the open set; naming `{COMPANY}_{PERIOD}_{TYPE}`; no LFS indicator seen, but the downloader asserts the response starts with `%PDF` and records the upstream commit SHA in `data/raw/financebench/MANIFEST.json`); fallback `doc_link` (sec.gov) via EdgarClient.
- SEC EDGAR (public domain): `https://www.sec.gov/files/company_tickers.json`; `https://data.sec.gov/submissions/CIK##########.json`; `https://www.sec.gov/Archives/edgar/data/{cik_int}/{accession_nodash}/{primary_doc}`; `https://data.sec.gov/api/xbrl/companyfacts/CIK##########.json`. Fair access: max 10 req/s, declared User-Agent "Name email" → `SEC_USER_AGENT` env (validated to contain an email), token bucket 8 req/s, tenacity retries (5 attempts, exp backoff 1–30 s, jitter) on 429/503/network only, disk cache keyed by sha256(url) under `data/cache/edgar/`. EDGAR is touched only by CLI ingest paths, never at answer time.
- `data/companies.yaml` (committed, hand-curated): FinanceBench company name → ticker → CIK for the ~40 benchmark companies; the one manual data task.
- Pricing: `src/secqa/eval/models.yaml` with `as_of: 2026-09-11`, per-model input/cached-input/output $/1M: claude-opus-5 5/0.50/25, claude-sonnet-5 2/0.20/10, gpt-5.5 5/0.50/30, gpt-5.4-mini 0.75/0.075/4.50, text-embedding-3-small 0.02 (verify cached-input rates on Day 1; `secqa doctor` checks each configured model id against the vendor models endpoint).

### 4.2 Storage (single file `data/index.duckdb`, gitignored)
Tables: `documents`(doc_name PK, ticker, cik, company, form, fiscal_year, period_end, source_kind, source_url, source_sha256, n_pages, ingested_at); `pages`(doc_name, page_num, text, PK(doc_name,page_num)); `chunks`(chunk_id PK, doc_name, page_num, chunk_idx, section, text, n_tokens, embedding FLOAT[{dim}]); `xbrl_facts`(cik, ticker, taxonomy, tag, unit, fy, fp, form, start_date, end_date, val DOUBLE, accn, filed, frame); view `financials`; `index_manifest`(key, value) holding embedder name, dim, git_sha, chunk/page/doc/fact counts, built_at, sha256 of inputs, dataset revision. The embedding column width is created from `embedder.dim` at `init_schema` (never hard-coded); opening a store with a different embedder dim raises `IndexMismatch`. FTS: `PRAGMA create_fts_index('chunks','chunk_id','text', stemmer='porter', stopwords='english', overwrite=1)` rebuilt after every ingest batch; BM25 via `fts_main_chunks.match_bm25(chunk_id, ?)`; dense via `array_cosine_similarity(embedding, ?::FLOAT[dim])` brute force (~40k rows, <20 ms); hybrid = RRF(k=60) in Python. Parquet export for portability. Sizes: ~10k pages, ~35–45k chunks, ~60 MB vectors, DuckDB ~200 MB. Index tarball (`index-v0.1.tar.zst` = index.duckdb + manifest.json) published as a GitHub Release asset; container downloads it from `SECQA_INDEX_URL` at start, else builds the bundled 2-doc fixture index so it is healthy with zero config. Results and cassettes: `results/<config>/<run_id>/{config.json,predictions.jsonl,summary.json}` committed (small); cassettes `cassettes/<run_id>.tar.zst` are Release assets, never git.

## 5. Agent
Tools (JSON schema, additionalProperties=false, `strict: true` where supported): `search_filings(query, ticker?, fiscal_year?, form?, k≤10)`, `get_pages(doc_name, pages[≤3])` (≤6000 chars each, truncated flag), `lookup_company(name_or_ticker)` (documents + fiscal years available, from `documents`), `lookup_fact(ticker, metric, fiscal_year)` (curated metric → CURATED_METRICS fallback chain from `xbrl/tags.yaml`; returns value, concept used, unit, fy, accn, filed), `query_xbrl(sql)` (sqlglot-validated single SELECT/WITH over `xbrl_facts`/`financials`/`documents` only; denies DDL/DML/ATTACH/COPY/PRAGMA/INSTALL/LOAD, table functions read_csv/read_parquet/read_json/glob/read_text; LIMIT 200 forced; read_only connection in a worker thread with 5 s interrupt), `calculate(expression)` (ast whitelist: numbers, + - * / ** %, unary minus, parentheses, abs/round/min/max), `final_answer(answer, value?, unit?, citations[{ref, quote}], calculation?, abstain)`. Citation refs are `chunk:<chunk_id>` or `xbrl:<tag>|FY<fy>|<accn>`; a ref is valid only if that chunk/fact row was returned by a tool in this run; invalid refs → error tool result, one retry, then abstain.
Loop (`agent/loop.py`, manual, provider-neutral): messages=[user(question+hints)]; each step `provider.complete(messages, system=AGENT_SYSTEM, tools=TOOLS)`; execute all tool calls of a step, return all results in ONE tool message; tools never raise (return `{"error":...}`); stop on `final_answer`. Stopping rules in code: max_steps=8; max_tool_calls=12; identical (tool, arguments) 3× → abort; second consecutive failure of same tool → abort; cumulative input tokens > 200k or projected cost > `max_cost_usd` (default 0.50 eval / 0.25 API) → abort; wall clock 90 s → abort. Any abort triggers one final call with `tools=None`: "answer from gathered evidence or say INSUFFICIENT EVIDENCE", recorded `terminated_by='budget'|'max_steps'|'error'`. Text-only response with no tool call: accepted as final only if `final_answer` schema parses via json_schema; otherwise nudge once. Anthropic: `thinking={'type':'adaptive'}`, `output_config.effort='medium'` (agent) / `'low'` (judge), `tool_choice` auto only, no temperature (400 on Opus 5/Sonnet 5), fallbacks disabled in eval (refusal recorded as stop_reason). OpenAI: chat completions function calling, same schemas, `temperature=0` where accepted, `reasoning_effort` recorded. Guardrails: system prompt states retrieved text/SQL rows are data, injected instructions ignored; test injects "ignore previous instructions" into a fixture chunk; no network from any tool; SQL read-only at connection and parser level.

## 6. Grounding and citations
`CitationVerifier.verify(answer_text, refs, seen_chunks, seen_facts)`: for each chunk ref the model-supplied `quote` must be a normalised (casefold, whitespace/punctuation-collapsed, ≥20 chars) substring of the chunk text → `verified=True`; unverified citations kept with `verified=False` (never dropped); display `snippet` always taken from the store (first 300 chars) so nothing shown is fabricated. `grounded` = every numeric token in the answer (normalised with `textnum.parse_number`: $, commas, %, million/billion/thousand, parentheses negatives, ratio↔percent) appears in a verified quote, a verified xbrl fact, or a `calculate` result of this request. Deterministic metrics: `citation_verified_rate`, `grounded_rate`.

## 7. Evaluation protocol
Benchmark: FinanceBench open set, all 150, no filtering; breakdown by question_type. Index built with bge-small-en-v1.5 (local, default).
Definition of done (v0.1 matrix, 1 embedder): retrieval-only rows bm25/dense/hybrid (key-free, page_recall@{5,10,20}, evidence_overlap_recall, MRR); then closed_book, oracle, rag_hybrid, agent_hybrid × {anthropic:claude-opus-5, openai:gpt-5.5} = 8 LLM rows. Ablations if budget allows: rag_hybrid_docfilter, openai text-embedding-3-small, claude-sonnet-5 and gpt-5.4-mini cheap rows. Procedure: 10-question smoke per provider (Day 4) → 30-question pilot → extrapolate cost → commit to full rows within the author's cap (set in configs; runs resumable; partial rows shown as pending). Budget expectation (to be measured, not asserted): agent rows dominate; rough upper bound ≈ 150 q × (~25k in + ~2k out tokens) ≈ $30/row Opus-tier, ≈ $130 for 8 rows + ≈ $15 judging with Sonnet 5.
Metrics (metrics.py, all unit-tested): page_recall@k (any gold (doc,page) among distinct pages of top-k chunks); evidence_overlap_recall@k (≥50% char-overlap with evidence_text, robust to page offsets; disagreement with page_recall reported); gold_page_mrr; numeric_match (strict: model's structured `value` vs the single number in gold; None if gold has 0 or ≥2 numbers or prediction has no value; 1% rel tol; coverage reported); judge accuracy (tri-state correct/incorrect/abstain; judge sees question, gold answer, justification, prediction; JSON schema output; effort low); abstain_rate; hallucination_rate = incorrect/(correct+incorrect); faithfulness (judge extracts atomic claims, judges each against cited passages ONLY, gold hidden; = supported/total); citation_verified_rate, grounded_rate (deterministic); latency p50/p95 split retrieval vs LLM (LLM cache off during timed runs); cost_usd per question from usage × models.yaml (judge cost separate); tool_calls and llm_calls per question; failure taxonomy per incorrect answer: retrieval_miss / reasoning_error / calculation_error / tool_error / budget. Judge/numeric disagreements are reported side by side; numeric_match overrides the judge only when defined, and every override case is listed in `summary.json`.
Judge design: one fixed judge for every row (`anthropic:claude-sonnet-5`, effort low) so rows are comparable; judge-swap re-score of the two headline rows with `openai:gpt-5.4-mini`, Cohen's kappa reported; 30-question stratified human-labelled subset (`eval/human_labels.csv` with protocol) → judge-vs-human kappa; kappa < 0.6 marks accuracy cells "provisional". Judge prompts are frozen (hash recorded in every record) before the first real run; they are never edited after seeing results (revision = new judge_version, all rows re-judged from cassettes). Uncertainty: bootstrap 95% CI, 2000 resamples, seed 0; README states ±7–8 pp at n=150 and that overlapping CIs are not evidence.
Reproducibility: every real run records cassettes (`ReplayCacheProvider` mode=record); `secqa rescore --run <id>` recomputes all metrics and re-judges from cassettes with no keys; CI runs `secqa eval --config configs/rag_mock.yaml --limit 6` on the fixture corpus. `secqa report` regenerates RESULTS.md from committed summary.json files; pending cells read "pending (not run)" with the reason; mock numbers never appear in README. Error analysis: failures grouped by question_type, 5 cases described by financebench_id with our answer and category (no dataset text).

## 8. API contract (FastAPI, `secqa.api.app:create_app`)
- `GET /healthz` → 200 `{status:"ok"}` (no deps). `GET /readyz` → 200 `{status:"ready", chunks, documents, facts, embedder, provider}` or 503 while index/embedder load. `GET /version` → `{version, git_sha, index_manifest, prompt_hashes, judge_version}`.
- `POST /v1/ask` body `AskRequest{question: str(1..2000), ticker?: str, doc_names?: list[str], fiscal_year?: int, mode: 'rag'|'agent'|'closed_book'='rag', provider?: str ('mock'|'openai:<model>'|'anthropic:<model>'), k: int=8 (1..20), max_cost_usd?: float, include_trace: bool=true}` → 200 `AskResponse` (= Answer contract, see shared contracts). Errors as `application/problem+json` `{type,title,status,detail,request_id}`: 422 validation; 402 cost budget exceeded (partial trace); 403 mode not allowed for anonymous callers; 429 rate limited (slowapi 10 req/min/IP); 502 upstream provider error; 503 provider not configured; 504 wall clock exceeded.
- `POST /v1/search {query, ticker?, doc_names?, k=8, strategy='hybrid'}` → `{hits: [HitView]}`. `GET /v1/filings?ticker=` → `[DocumentMeta]`. `GET /v1/filings/{doc_name}/pages/{page}` → `{doc_name, page_num, text}`. `POST /v1/xbrl/query {sql}` → `SqlResult` (same guard as the tool; 400 SqlRejected).
- Middleware: X-Request-ID echoed/generated on every response; structlog JSON logs with request_id, provider, model, tokens, cost, latency; Server-Timing header. No ingest endpoint (ingest is CLI-only; ADR-07). `SECQA_API_KEY` optional: when set, `agent` mode and non-default providers require `X-API-Key`. Public demo runs provider=mock unless a key is in Secret Manager; per-request cost cap and per-instance daily cap `SECQA_DAILY_BUDGET_USD` (in-memory, documented as per-instance).

## 10. Deployment and CI
Docker (`Dockerfile`, multi-stage, built in CI since no local daemon): stage 1 `ghcr.io/astral-sh/uv:python3.11-bookworm-slim`, `uv sync --frozen --no-dev --extra local` (target `full`) or `--extra api-embeddings` (target `slim`); bge-small weights baked into `full` at build (no HF download at runtime); stage 2 python:3.11-slim, non-root `app`, HEALTHCHECK /healthz, `CMD uvicorn secqa.api.app:app --host 0.0.0.0 --port ${PORT:-8080}`. Startup: download `SECQA_INDEX_URL` (https or gs://) to /data if absent else fixture index. Secrets only via env (`OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `SEC_USER_AGENT`, `SECQA_API_KEY`); `.env.example`; gitleaks in CI and pre-commit.
Workflows: `ci.yml` (PR/push: uv sync, ruff check+format, mypy non-blocking, `pytest -m "not live and not slow" --cov`, mock smoke eval, docker build no push); `build.yml` (main/tags → GHCR `ghcr.io/<owner>/sec-filing-qa:{sha,latest}`, targets full+slim); `deploy-cloudrun.yml` (tag v* or dispatch; guarded `vars.DEPLOY_GCP=='true'`; WIF auth; `gcloud run deploy sec-filing-qa --image ...:<sha> --region us-central1 --memory 2Gi --cpu 1 --cpu-boost --min-instances 0 --max-instances 2 --concurrency 4 --timeout 120 --set-secrets ... --set-env-vars SECQA_INDEX_URL=...`; first deploy done by hand with local gcloud on Day 5); `deploy-azure.yml` (dispatch/tag; guarded `vars.DEPLOY_AZURE=='true'`; azure/login OIDC federated credential; `az containerapp create|update` per `infra/azure/main.bicep`, min 0 / max 2 replicas, 1 CPU / 2 Gi, ingress 8080); `eval-full.yml` (dispatch only, needs repo secrets, commits results/ to a branch → PR). Both deploys end with a smoke step: curl /readyz and one /v1/ask provider=mock, JSON pasted into the job summary. Cold start of `full` (~1.6 GB) is 10–20 s; documented; `min-instances 1` optional during interview weeks.

## 11. Risks (mitigation)
Page-offset bug (check script gates publication; overlap recall cross-check) · PDF table flattening (oracle row + taxonomy expose it; pdfplumber future) · CC-BY-NC (ids only in results) · n=150 (CIs, no winner declared) · judge bias (fixed judge, swap kappa, human kappa, numeric side-by-side, frozen prompts) · Azure has no local tooling (portal setup Day 1; wording rule) · cost (smoke→pilot→extrapolate, per-run caps, cassettes so nothing is paid twice) · Anthropic has no embeddings (local default; OpenAI ablation) · EDGAR blocking (8 rps, UA, cache, CLI-only) · prompt injection (prompt + read-only tools + test; stated limitation) · model ids/prices drift (recorded per run; `secqa doctor`) · sampling params rejected on Opus 5/Sonnet 5 (provider omits temperature; recorded) · PDFs missing upstream (magic-byte check, doc_link fallback, doc_unavailable count) · scope creep (matrix above is done; else issue tracker).
